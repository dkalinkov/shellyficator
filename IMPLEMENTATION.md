- Environment-supplied shared credentials for reading protected devices; device credentials are separate from dashboard accounts.
- Embedded static assets, build scripts, and a container running as a non-root user with persistent data.

## Operational details

For development, run `make dev`. Air 1.67.4 is pinned through Go's tool dependency mechanism. Source changes rebuild the UI assets and embedded Go binary, then restart the app on localhost:8090 using `pb_data/`. Go, template, JavaScript, and CSS reloads were verified with temporary source edits, including serving the changed template/assets over HTTP. Failed builds serve the previous binary and recover after fixing the source. Generated assets and database files do not cause restart loops; all probe edits were restored. Go tests passed. Browser refresh remains manual for new CSS/JavaScript. See [the development workflow](README.md#development-with-automatic-restarts) and [.air.toml](.air.toml).

Keep `pb_data/` (or the container's `/data`) outside Git and preserve it across upgrades. Configuration snapshots contain readable/redacted API settings; they are not complete device backups. PocketBase data admin has full access to the database and can change records, including snapshot history.

Dashboard and data admin accounts start with matching credentials but are separate records. Change or recover operator credentials through Data admin. Shared device credentials come from the process environment and are never inserted into device UI links. The current application exposes no device mutation endpoints.
